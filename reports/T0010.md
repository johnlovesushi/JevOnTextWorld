# T0010: SFT data without redundant `open` commands; several levels in one SFT run

Issue #38. Branch `task/T0010-sft-data`, cut from `exp/E0012-verbal-confidence` at 7c90c68 (it depends on PR #37 for
the two-GPU SFT of T0009).

## What changed
- `scripts/build_sft_data.py` now skips a redundant `open X` by default. A redundant open is one where X is already
  open: `open X` is not admissible but `close X` is. The script calls the same
  `diagnose_history.walk(..., skip_redundant_open=True)` that E0011 added and `scripts/check_games.py` uses. A
  skipped command gives no state. `--keep-redundant-open` restores the old behaviour.
  When skipping, the statistics also report `redundant_open_skipped` and `games_with_redundant_open`.
- `jevtw.sft --train-data` takes one or more files, and their states are pooled and shuffled together.
  - Every state gets a level label: the row's own `level` if it has one, otherwise the file name
    (`C3_train.jsonl` → `C3`).
  - With more than one level, each train line also has `sft_loss_<level>`, `train_acc_<level>` and
    `decisions_<level>`. These are summed across processes under torchrun.
  - With a single file, the log is unchanged.
- Two GPUs: `jevtw.sft` already ran under torchrun (T0009). The new test checks that 2 processes give the same
  metrics as 1.
- Docs: `docs/implementation.md` (the SFT data section and the test table) and `README.md`.

## Statistics: C1–C4 training sets (200 games each)

"Before" is the script at 7c90c68. "After" is the new default. With `--keep-redundant-open` the new script's
`.jsonl` and `.stats.json` are byte-identical (`cmp`) to "before" on all four levels.

| Level (train) | Games | Kept before | States before | Kept after | States after | Still dropped | Skipped opens (games) |
|---|---|---|---|---|---|---|---|
| C1 | 200 | 200 (100.0%) | 1709 | 200 (100.0%) | 1709 | 0 | 0 (0) |
| C2 | 200 | 101 (50.5%) | 1623 | 200 (100.0%) | 3354 | 0 | 111 (99) |
| C3 | 200 | 200 (100.0%) | 2024 | 200 (100.0%) | 2024 | 0 | 0 (0) |
| C4 | 200 | 73 (36.5%) | 1289 | 200 (100.0%) | 4315 | 0 | 274 (127) |

Games dropped before the fix, by the walkthrough command that was not admissible:
- C1: none
- C2: 'open fridge' × 99
- C3: none
- C4: 'open fridge' × 63, 'open patio door' × 26, 'open sliding patio door' × 22, 'open screen door' × 16

After the fix, **no game is dropped on any level**, so the T0010 stop condition (more than 10% dropped) is not
triggered. On C1 and C3, which have one ingredient, nothing was skipped, and the new `.jsonl` is byte-identical to the
old one. On C2 and C4, all the dropped games are recovered, and the number of states roughly doubles (C2) or triples
(C4). This is because the dropped games were the ones with more ingredients, which have longer walkthroughs.

The data is in `data/sft/T0010/{before,keep,after}/C*_train.jsonl` and is not committed.
E0013 uses `data/sft/T0010/after/C1_train.jsonl` and `data/sft/T0010/after/C3_train.jsonl`, which get the labels
`C1` and `C3`.

## Tests (CPU, `tests/test_t0010.py`)
1. A game with a redundant `open fridge` (the fake environment from the E0011 test): the data follows the walkthrough
   without the second open, has the same states as the same game without it, and the stats count one skipped open.
   With `--keep-redundant-open`, the game is dropped with the old reason.
2. `--keep-redundant-open` writes exactly the bytes of the old script, which the test takes from git at 7c90c68.
   Checked on the fake games and on a real tw-cooking game.
3. Two files pooled: the number of states equals the sum of the two files and the labels are correct. In a
   `jevtw.sft --smoke` run, the per-level loss and accuracy, weighted by state counts, equal the pooled values.
4. `torchrun --nproc-per-node=2` SFT gives the same metrics as one process (loss and per-level values to 1e-4;
   accuracy, counts and validation win rate exactly).
5. The full suite: see the PR.

## Decisions needed
None. The defaults, GRPO, calibration and prompt code are unchanged, and nothing was trained.
